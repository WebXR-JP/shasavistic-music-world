# 画面共有パネルのホスト確認（一時的検証計画）

この文書は一時的な検証計画であり、実行形の検査で表せないホスト環境の画面共有パネルの受入れ条件だけを置く。開発環境（`XRiftProvider` の既定 no-op）で確認できるのは非共有時の見え方と配置までであり、共有開始・他参加者への表示・通話ルーム加入の要否はホストで判定する。対応する判定処理が完成した項目から削除し、項目がなくなったらこの文書を廃止する。方式の正本は `workflow/design/shasavistic-music-lab/pitch-grid/screen-share.md` による。

## 未実装条件

- ホスト環境で、奥壁の画面共有パネルをInteractして自分の画面共有を開始・停止できることを判定する。開発環境の既定動作（no-op、`isRoomConnected:false`）の成功はホストの合格証拠にしない。
- ホスト環境で、共有中の映像が同室の他参加者に表示されることを二つの参加端末で判定する。
- ホスト環境で、ワールド内の共有画面が一面であることを判定する。
- ホスト環境で、共有開始が通話ルーム加入やマイク有効化を不可避に要求するかを観測して記録する（合否ではなく事実記録）。要求する場合は非目標との整合を人間の判断へ戻す（設計の見直し条件）。
- ホスト環境で、スポーンおよび接近時に共有面を狙って操作できた立ち位置と距離を記録する（設計の見直し条件の判定材料）。
- ホスト環境で、パネルが奥壁の内側・地面より上に収まること、および理論説明パネルと投影上重ならないことを判定する。格子越しの遮蔽は許容であり不合格にしない。
- `xrift.json` に画面共有専用の設定が必要かを実機で確認する（現時点で確認できていない。設定不要の証明ではない）。

## 必要な環境

- 利用者が公開した今回の版（`xrift upload world`。ビルドと自動コード審査の通過が前提。旧公開版の結果を今回の結果にしない）
- 入室できるインスタンス
- 共有操作を行う端末と、表示を確認する同一室の他参加端末
- 画面共有の開始が許可されるブラウザ環境（画面選択の許可・取消ができること）

## 実行手順

段取りは公開前提の確定、インスタンス入室、非共有時の見え方の記録、共有開始・停止、他端末での表示確認、狙いやすさの記録の順とする。

- 非共有時は、パネルの見え方と表示文言（開発環境では「音声通話に接続できていません」）を記録する。ホストでの文言の違いも記録する。
- 共有操作では操作と前後の状態を記録する。
- 他端末では表示の有無を、各端末の環境・入室方式・音の出る状態とともに記録する。

## 残す証拠

- ホスト結果は `shasavistic-music-lab/tmp/host-confirmation/` に置く。雛形 `workflow/spec/host-confirmation-evidence.template.json` の `screenShare` 欄を複写して記入し、開発環境の採取証拠と混同しない。
- `screenShare.operations` に操作時系列、`screenShare.checks` に項目別結果（`pass`・`fail`・`unobserved` のいずれか。`unobserved` は理由を記す）を記入し、該当操作IDを参照する。
- 通話ルーム加入・マイクの要否、狙えた立ち位置、設定の要否は事実記録欄に残す。
- 利用者は雛形を複写して記入し、上記の置場に保存して戻す。判定可能になった項目はこの計画から削除し、実行形（検査または再実行可能な手順と証拠判定）へ移す。

記入値の許容列挙はこの計画に置く。`operations` の `action` は `start`・`stop` のいずれか一つとする。
