# 調波シンセの未実行受入れ条件（一時的検証計画）

この文書は一時的な検証計画であり、実行形の検査で表せないホスト環境と物理出力の受入れ条件だけを置く。`npm run test:interact`（`src/audio/harmonicInteract.capture.test.ts`）は旧4 Cube聴き比べ経路の実操作起点の信号生成を覆い、15点・移動・次元切替は覆わない（現物確認済み。廃止経路の残存検査でありMVP回帰対象外。`workflow/design/shasavistic-music-lab/harmonic-synth/sound-cubes.md:9` 参照）。開発環境の格子操作の採取は未整備であり、対応する判定処理の完成時にこの計画へ反映する。対応する判定処理が完成した項目から削除し、項目がなくなったらこの文書を廃止する。要求の最大15点同時とノコギリ波固定の判定は開発格子採取へ移す予定であり、ホスト確認の雛形には加えない。

## 未実装条件

- ホスト環境での音声許可と文脈再開を判定する。開発環境の採取成功と混同しない。文脈の状態表示だけでは合格としない。
- ホスト環境で格子の表示、各点のオン・オフ、複数音の発音と停止を判定する。
- ホスト環境でオン集合の八方向への移動、端での停止、縦軸の切替を判定する。切替時は旧音が止まり、オン座標を保ったまま新次元で鳴らし直されることを含む。途切れは許容する。
- ホスト環境で合成の頂上と音量の異常の有無を人の聴取で判定する。総利得予算は過大振幅を避ける設計上の上限であり、音量の保証ではない。校正した測定器と承認基準がないため、音圧と歪みは保証しない。
- 物理出力を人の聴取で確認する。音声グラフ内の標本は信号生成の証明に含めない。

## 必要な環境

- 利用者が公開した今回の版（`xrift upload world` による公開。ビルドと自動コード審査の通過が前提であり、不通過ならホスト判定に進まない。旧公開版の結果を今回の結果にしない）
- 入室できるインスタンス（`https://app.xrift.net/instance/<instanceId>`。用意と入室は利用者が行う）
- 音を聴ける端末と出力装置（消音状態を対照にできること）
- 機械採取を行う場合だけ、対象ワールドの信号を同定できる採取手段

## 実行手順

段取りは公開前提の確定、インスタンス入室、実操作、判定の順とする。各段で記録する欄は雛形による。

- 公開前提の確定では、world ID、ビルドや版、アップロード日時を控え、今回の公開版であることを確かめる。
- インスタンス入室では、instance ID、日時、入室方式を控える。
- 実操作では、対象と操作順を記録しながら、格子の表示、各点のオン・オフ、複数音の発音と停止、八方向への移動、端での停止、縦軸の切替の順に操作する。
- 判定では、文脈の状態や画面表示だけを合格にしない。

聞こえない場合は、音量、出力先、タブ消音、入室状態とブラウザ内信号の有無を切り分ける。ブラウザ信号はあるが聞こえない場合は、物理出力を不合格または原因未特定とする。入室できて無音の場合は、ホスト許可、入力到達、ブラウザ信号、出力先を分離して再相談する。

機械採取は可能な範囲で任意とする。対象ワールドの信号を同定できれば、操作前後の無音対照、成分、持続と減衰と最終消音、和音時の波形頂上を採取する。同期できない場合や対象を同定できない場合は、数値を合格証拠にせず対象の採取不可とする。`--mute-audio` を付ける採取は物理出力の証拠にならない。ホスト自身の音声文脈とワールドの文脈を区別できない場合は、無条件にワールドの証拠としない。

物理出力は人の聴取を別記録とする。消音状態を対照に、同じ端末と出力装置と音量設定で、操作後に聞こえること、オン・オフと移動と切替の区別が付くこと、目立つ割れや不快な音量がないことを項目別に記録する。聴き分けの項目は定義した操作に対する観察として合否化してよいが、音色の良し悪しや音量の適切さの普遍的な数値合格とはしない。

## 残す証拠

- ホスト環境の結果は `shasavistic-music-lab/tmp/host-confirmation/` に置き、開発環境の採取証拠と混同しない。雛形は `workflow/spec/host-confirmation-evidence.template.json` を複写する。認証情報や個人情報は保存しない。
- 記録する欄は、公開版の識別子（world ID、ビルドや版、アップロード日時）、instance ID、日時、ブラウザや端末や出力装置や音量設定、入室方式、操作時系列（操作ID・時刻・対象/方向・操作前後の状態）、項目別の結果と該当操作ID、採取元と測定値、ホスト許可と再開、聴取の項目別結果、失敗と取得不可と未観測の区別とする。機械採取と物理聴取を一つの音が出たにまとめない。
- 項目別の結果欄は、格子表示、各点オン・オフ、複数音の発音と停止、八方向の移動（`moveEightDirections` の1欄に集約）、端で集合全体が移動しない、空集合の移動で発音しない、次元切替で旧音が止まる、切替でオン座標が保たれる、同じ点を新次元で鳴らし直せる、説明パネルが読める、の別項目とし、各欄に `pass`・`fail`・`unobserved` のいずれか一つを記入し、該当操作IDを参照する。`unobserved` には理由を記す。`moveEightDirections` は八方向すべて確認できた場合に `pass` とし、方向別に分ける場合は `note` に方向を記す。未実施の方向がある場合は `note` に残し、全体を `fail` または `unobserved` とする。ホスト許可と再開、割れと不快音量、物理聴取は別欄に残す。切替の記録では縦座標が非ゼロの点を含め、切替前後のオン座標・次元表示と、旧音停止・新音聴取を別々に記録する。説明の可読は1枚の全文・格子の奥側・近寄った視点で確かめ、公開版・視点・読めた範囲を `note` に残し、文面の理論的妥当性と利用者承認はホストの「見えた」判定とは別証拠とする。人による聴取と音声グラフ採取を混同しない。
- 記入値の許容列挙はこの計画に置く。`operation.action` は `grid-on`・`grid-off`・`grid-move`・`dimension-switch` のいずれか一つ、`capture.result` は `obtained`・`target-unidentified`・`not-attempted` のいずれか一つとする。雛形の例は単一値を記す。ホスト許可と再開、聴取の項目別結果は自由記述とし、失敗・取得不可・未観測の区別は記録欄に記し、該当すれば操作IDを参照する。
- 利用者は雛形を複写して記入し、上記の置場に保存して戻す。判定可能になった項目はこの計画から削除し、実行形（検査または再実行可能な手順と証拠判定）へ移す。未実行と未観測の条件は残す。
