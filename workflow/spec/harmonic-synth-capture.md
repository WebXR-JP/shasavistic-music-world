# 調波シンセの未実行受入れ条件（一時的検証計画）

この文書は一時的な検証計画であり、実行形の検査で表せないホスト環境と物理出力の受入れ条件だけを置く。開発環境の実操作起点の信号生成は `npm run test:interact` が覆うためここに置かない。対応する判定処理が完成した項目から削除し、項目がなくなったらこの文書を廃止する。

## 未実装条件

- ホスト環境での音声許可と文脈再開を判定する。開発環境の採取成功と混同しない。文脈の状態表示だけでは合格としない。
- ホスト環境で単声の持続とノートオフ後の減衰・消音の聴き分けを判定する。
- ホスト環境で和音の聴き分け（単声を含む組合せ間の移動）と全声の減衰完了後の次和音の進行、減衰中の操作が次和音を重ねないことを判定する。
- ホスト環境で合成の頂上と音量の異常の有無を人の聴取で判定する。総利得予算は過大振幅を避ける設計上の上限であり、音量の保証ではない。校正した測定器と承認基準がないため、音圧と歪みは保証しない。
- 物理出力を人の聴取で確認する。音声グラフ内の標本は信号生成の証明に含めない。

## 必要な環境

- 利用者が公開した今回の版（`xrift upload world` による公開。ビルドと自動コード審査の通過が前提であり、不通過ならホスト判定に進まない。旧公開版の結果を今回の結果にしない）
- 入室できるインスタンス（`https://app.xrift.net/instance/<instanceId>`。用意と入室は利用者が行う）
- 音を聴ける端末と出力装置（消音状態を対照にできること）
- 機械採取を行う場合だけ、対象ワールドの信号を同定できる採取手段

## 実行手順

段取りは公開前提の確定、インスタンス入室、実操作、判定の順とする。各段で記録する欄は雛形による。

- 公開前提の確定では、world ID、ビルドや版、アップロード日時を控え、今回の公開版であることを確かめる。
- インスタンス入室では、instance ID、日時、入室方式を控える。
- 実操作では、対象と操作順を記録しながら、単声の持続、ノートオフ後の減衰と消音、次の和音、和音の停止の順に操作する。
- 判定では、文脈の状態や画面表示だけを合格にしない。

聞こえない場合は、音量、出力先、タブ消音、入室状態とブラウザ内信号の有無を切り分ける。ブラウザ信号はあるが聞こえない場合は、物理出力を不合格または原因未特定とする。入室できて無音の場合は、ホスト許可、入力到達、ブラウザ信号、出力先を分離して再相談する。

機械採取は可能な範囲で任意とする。対象ワールドの信号を同定できれば、操作前後の無音対照、成分、持続と減衰と最終消音、和音時の波形頂上を採取する。同期できない場合や対象を同定できない場合は、数値を合格証拠にせず対象の採取不可とする。`--mute-audio` を付ける採取は物理出力の証拠にならない。ホスト自身の音声文脈とワールドの文脈を区別できない場合は、無条件にワールドの証拠としない。

物理出力は人の聴取を別記録とする。消音状態を対照に、同じ端末と出力装置と音量設定で、操作後に聞こえること、持続と減衰と消音を区別できること、単声と和音を区別できること、目立つ割れや不快な音量がないことを項目別に記録する。聴き分けの項目は定義した操作に対する観察として合否化してよいが、音色の良し悪しや音量の適切さの普遍的な数値合格とはしない。

## 残す証拠

- ホスト環境の結果は `shasavistic-music-lab/tmp/host-confirmation/` に置き、開発環境の採取証拠と混同しない。雛形は `workflow/spec/host-confirmation-evidence.template.json` を複写する。認証情報や個人情報は保存しない。
- 記録する欄は、公開版の識別子（world ID、ビルドや版、アップロード日時）、instance ID、日時、ブラウザや端末や出力装置や音量設定、入室方式、操作時系列、採取元と測定値、聴取の項目別結果、失敗と取得不可と未観測の区別とする。機械採取と物理聴取を一つの音が出たにまとめない。
- 利用者は雛形を複写して記入し、上記の置場に保存して戻す。判定可能になった項目はこの計画から削除し、実行形（検査または再実行可能な手順と証拠判定）へ移す。未実行と未観測の条件は残す。
